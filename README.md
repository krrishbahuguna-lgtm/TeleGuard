
TELEGUARD: TELECOM RETENTION & CHURN INTELLIGENCE

PROJECT INFORMATION

Project Title: Customer Churn Risk Profiler for the Telecom Industry
Working Group: G2
Group Number: 14

TeleGuard is a menu-driven, Python-based decision-support system developed for a simulated telecom operator. It analyses customer churn patterns, estimates customer-level churn probabilities using Logistic Regression, groups customers into Low, Medium and High risk categories, and presents visualisations to support customer-retention decisions.

The project uses an independently generated synthetic dataset. The IBM Telco Customer Churn dataset was used only as an external reference for variable selection and terminology. IBM customer records, churn rates and results are not used as the project's results.

IMPORTANT:
The dataset is synthetic. Model probabilities and findings describe this simulated dataset; they are not guaranteed predictions about real telecom customers. Observed relationships are statistical associations and should not be interpreted as proof of causation.

4. USING THE TELEGUARD INTERFACE

TeleGuard provides a menu-driven way to access the project's analysis and estimate the churn risk of a hypothetical customer.

The main menu contains four options:

1. Analyse Customer Churn

Runs the project's existing analytical functions. It displays the dataset overview, business KPIs, customer segmentation, model evaluation, customer risk profiles and churn-associated factors. It also refreshes the two analysis output CSV files.

2. Check a Customer's Churn Risk

Allows the user to enter a hypothetical customer's details and obtain an estimated churn probability and a Low, Medium or High risk classification.

The program requests the model's numerical and categorical input features. Enter numerical values within the displayed ranges and select from the displayed category options. The interface validates entries and asks again when an input is invalid.

The model uses the same feature definitions and preprocessing pipeline as code-analysis.py. The probability is an estimate, not a guarantee that the customer will leave.

3. Help & Guide

Opens the built-in guide, which explains:

- How to operate the system.
- Statistical concepts.
- Business terminology.
- Understanding results and risk categories.
- Troubleshooting and common errors.

4. Exit

Closes the TeleGuard application.

The individual customer risk option trains the project's Logistic Regression pipeline using the available synthetic dataset before making the prediction. It does not use a separate prediction model.

NOTE:
The menu runs the analysis and customer-level prediction functions. Dataset generation and chart generation are performed separately using the respective scripts described in Section 3.


5. MODEL AND RISK CATEGORY NOTES

The project uses Logistic Regression because churn is represented as a binary outcome:

0 = Customer retained
1 = Customer churned

The model estimates a probability between 0 and 1.

For example, a predicted probability of 0.35 is displayed as 35%. This means the model assigns that customer an estimated churn probability of 35%; it does not mean churn is certain.

The project's customer risk bands are:

- Low Risk: Predicted probability below 15%.
- Medium Risk: Predicted probability from 15% to below 30%.
- High Risk: Predicted probability of 30% or above.

These are project-defined operational categories, not universal telecom-industry standards.

The model's classification threshold used for final evaluation is 0.25. This threshold is distinct from the three customer risk-band boundaries above.

A classification threshold converts a probability into a predicted class, whereas risk bands group customers for prioritisation.

7. IMPORTANT INTERPRETATION AND LIMITATIONS

- The dataset is synthetic and independently generated for this academic project. Results should not be treated as actual telecom-industry statistics.
- The model identifies patterns in the simulated data. Associations between customer attributes and churn do not establish causation.
- Model performance is not perfect. Some customers flagged as high risk may remain with the service, and some customers who churn may not be identified by the model.
- False positives and false negatives are important when interpreting the confusion matrix.
- Retention teams should use model scores as decision-support information, not as automatic decisions.
- The risk categories are project-defined and should be reviewed before use in a real business setting.
- Customer-level outputs and recommendations should be interpreted within the scope and limitations of the simulated dataset.

# TeleGuard — Telecom Customer Churn Risk Profiler

TeleGuard is a menu-driven Python decision-support project that analyses customer churn patterns in a simulated telecom dataset. It uses Logistic Regression to estimate customer-level churn probabilities, assigns Low, Medium, or High risk categories, and generates visualisations to support retention decisions.

> **Data and interpretation:** The dataset is synthetic and independently generated for this academic project. The IBM Telco Customer Churn dataset was used only as a reference for variable selection and terminology. TeleGuard's results are not real-world telecom statistics, and statistical associations should not be interpreted as causal relationships.
